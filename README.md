# Order To Cook Addon（下单了：附属）

**当前版本：1.1.0**（更新日志：[中英双语](CHANGELOG.bilingual.md) / [中文](CHANGELOG.zh-CN.md) / [英文](CHANGELOG.md)）

从源码构建见 [BUILD.md](BUILD.md)（JDK 21 + Gradle 8.8+，产物 `build/libs/otcaddon-1.1.0.jar`）。

提供悦灵服务员、储钱罐、JEI 菜单快捷添加与缺料收藏、外卖指路箭头，并顺带压掉前置本体顾客动画的报错刷屏。

## 环境与安装

- Minecraft **1.21.1**，NeoForge **21.1.244+**。
- 需要 Order To Cook 本体 **1.3.6 或兼容后续版本**，不再要求 1.3.7a。已核对正式版 1.3.6 jar 中的本体调用接口与收付款接入点；实际游戏流程仍需实测。
- JEI **19.57.0.449+** 可选；收藏与菜单快捷添加需要它。
- 用 `otcaddon-1.1.0.jar` 替换旧附属，不要同时保留两个版本。多人游戏客户端、服务端一起更新。
- 更新旧世界前建议备份存档。

## 悦灵服务员

打单机右侧的「升级悦灵」按钮，第一次点击雇佣1级悦灵，之后每次升一级。
**每台打单机最多一只**，等级不得超过餐厅等级，最高8级；不再提供 Shift 解雇按钮。

| 等级 | 能做的事 | 飞行速度（格/秒） | 找活基础间隔 |
| --- | --- | --- | --- |
| 1 | 送打包袋、餐盘；顾客摆盘位置有脏盘时不送 | 2.08 | 4秒 |
| 2 | 新增收脏盘，送入洗碗机或洗碗池 | 2.53 | 3.5秒 |
| 3 | 新增在洗碗池洗碗、从洗碗机取净盘、把空盘放回餐盘架 | 2.97 | 3秒 |
| 4 | 保留全部能力，提速 | 3.42 | 2.5秒 |
| 5 | 保留全部能力，提速 | 3.86 | 2秒 |
| 6 | 保留全部能力，提速 | 4.31 | 1.5秒 |
| 7 | 保留全部能力，提速 | 4.75 | 1秒 |
| 8 | 达到上一版的最高飞行与响应速度 | 5.20 | 0.5秒 |

上述速度按正常20刻/秒计算；靠近目标仍平滑减速，找活调度最多额外等待0.5秒。
洗碗池每只盘子洗4秒，有水花；3级以下仍要玩家手动洗池内的盘子。

- **费用**：雇佣及后续每级依次为100、200、400、800、1600、3200、6400、12800 otc币，优先从储钱罐扣款，不足再扣玩家身上的币。
- **工作范围**：打单机水平24格、上下12格内，只查看已加载区块。先处理手持物品，再送餐、清盘和洗碗。
- **餐盘架**：使用本体餐盘架，最多18只；没有空位时，悦灵保留手中空盘等待，不删除或复制餐盘。
- **老板离线或换维度**：沿用原版附属行为，悦灵待命，保留物品，不继续送餐。
- **旧存档**：原雇佣数量迁移为已购等级，多只实体合并为一只；多余悦灵手里的物品掉回原位，不额外退费或扣费。餐厅等级降低只限制生效能力，不抹掉已购等级。
- **桌前脏盘**：检查本体指定的顾客摆盘位置，不凭朝向猜位置；取餐前、交付前均检查。途中新增脏盘时，餐点退回取餐位置掉落，避免覆盖脏盘和错误结算。

## 储钱罐

- 合成：工作台中心放一个箱子，上下左右各放一块红砖；也可在创造模式「功能方块」找到。
- 物品编号：`otcaddon:money_jar`。外观沿用 r38 的**粉色小猪储蓄罐模型和原贴图**，不再是紫黑占位方块。
- 右键打开9格容器，仅接受本体1、5、20、100、10000面额otc币。普通物品不能放入。
- 放在打单机周围一格内即可连接：以打单机为中心的3×3×3范围，包含上下和斜角；不需要额外绑定。
- 订单收入与小费直接优先存罐，不先经过背包；包括到店、外卖和顾客特殊额外奖励。按订单所属打单机结算，不按玩家当前位置猜餐厅。
- 多个罐子按距离、坐标依次使用。放不下的金额按本体规则交给玩家；背包也满时由本体处理掉落。
- 打单机升级、收费改名、悦灵雇佣和升级，都能使用罐内货币。优先扣罐子，不足再补背包；余额不够时不会扣走罐内的钱。
- 支持高面额币找零；找零优先放回罐内。正常收款不把已有零钱强行合并成大面额币。
- 拆除储钱罐会掉出里面的币，容器内容随世界保存。收入只写入已加载的罐子，未加载时回退原发币方式。
- 如果本体启用了自定义货币或 SDM 账户货币，保持本体收付款方式，不把账户余额强行兑换成otc币。

## 前置动画报错消音

- 现象：`[Render thread/ERROR] [GeckoLib/]: Unable to find animation: customer_sit_1 for CustomerEntity`
  每帧刷一条，日志能涨到几百 MB；同时顾客僵在原地不动，打单机也不播动画。
- 真正的原因（已用 GeckoLib 4.9.3 实际复现并验证）：**问题不在前置，而在 GeckoLib 的载入方式。**
  GeckoLib 用一个不带逐文件容错的循环去烘焙所有模组 `assets/<命名空间>/animations/` 下的动画文件；
  只要其中**任意一个**文件解不开（例如某个模组把 `.geo.json` 模型文件错放进了 `animations` 目录，
  或者 JSON 结构不合规），循环就直接中断，**排在它后面的动画文件整批被丢掉，而且一条日志都不留**
  （异常挂在一个没人接的异步任务上，被静默吞掉了）。
- 已核对：Order To Cook 1.3.6 自己的 11 个动画文件内容完全正常，只和 GeckoLib 一起加载时
  一次全部烘焙成功（`customer_sit_1~4`、`customer_wait_1~4`、`npc_sitspawn`、`neworder` 都在）。
  它是和别的模组一起加载时才被挤掉的——所以刷屏与前置版本无关，也和「缺 1、3 号变体」无关。
- 处理一（治本）：资源加载完成后自查一遍 GeckoLib 的动画缓存，把缺失的文件用 GeckoLib 自己的
  `FileLoader.loadAnimationsFile` 重新烘焙补回；那个真正坏掉的文件单独跳过，不连累其他文件。
  补回后顾客动画照常播放，报错自然也就不再产生。
- 处理二（兜底）：日志过滤器拦掉正文含 `Unable to find animation:` 的条目，覆盖补缓存生效前的空档。
  GeckoLib 的其他报错照常显示，不会一起被吞掉。
- 两项都不需要改前置或别的模组的文件，也不影响存档；实现全部走反射 + 异常保护，
  取不到接口时最坏结果只是「不生效」，不会让游戏崩溃。
- 另外提醒：前置作者在 1.3.6 的更新说明里写明 **1.21.1 请搭配 geckolib 4.8.4**。
  本附属的修复正是针对 4.9.3 验证的，用 4.9.3 也没问题；想完全按作者测试过的组合走，就换成 4.8.4。

## 原有便捷功能

- 立牌菜单打开时，按住 Shift 点击 JEI 里的食物即可加入。
- 操作台右上角缺料查询会将缺少菜品加入 JEI 收藏；打包或装盘成功后只撤掉这次自动加的收藏。
- 主手拿着打包好的外卖袋时显示配送指路箭头。
